## 输入契约

以下字段构成一个 JSON 请求。`repo`、`report`、`producer_manifest` 都是调用进程可读的本地路径，HTTP 角色负责把 URI 下载结果映射到这些路径。

| 字段 | 约束 |
| --- | --- |
| `profile` | 必填，`explicit` 或 `tinyexpr` |
| `repo` | 必填，包含目标提交的 Git 仓库路径 |
| `target` | 必填，完整 40 位小写提交 SHA |
| `report` | 必填，原始 JSON 报告文件路径 |
| `report_sha256` | 必填，64 位小写 SHA-256，取自调用方已取得的可信清单或传输响应 |
| `producer_manifest` | E12 实际报告必填，原始生产者 `result.json` 路径；固定报告验证可省略 |

提供生产者清单时，报告必须为 `kind=incremental-check`，清单和报告须为 `e11e12-1`、`SUCCEEDED`，内层报告为 `e8e10-1`。清单的 target、报告内外层 commit 均须匹配 `target`；阶段 URI、job/trace 和报告摘要逐项绑定。省略清单时只接收 `fixed-md`，适合独立组件验证。HTTP 层应从任务模式决定是否强制生产清单，正式 E12 使用前一种入口。

`fixed_report_sha256` 是教师公共请求中的字段；成员 3 适配时显式映射为本组件的 `report_sha256`。共享旧 `e11-b` pipeline 是否读取该字段属于其编排接入工作，应按实际接入路径做测试。

传输侧负责 URL/URI 解析、下载权限、路径准入、超时、下载响应原件与哈希来源。组件负责实际文件摘要校验、生产者身份和完整提交绑定，并在独立 Git 检出副本上修复。外层 HTTP job/trace 由成员 3 管理，原生产者 ID 保留在 `result.input` 中。

## 支持范围

`explicit` 使用既有 `lab.patch` 和 `lab.validate`，要求 `main.c/helper.c/config.h` 布局、显式对象声明及既有受支持的 CFLAGS。行为断言为初始输出 `1`、改 `config.h` 后输出 `2`，构建为 `make app`。教师 H2-inih 课程适配仓库满足这组结构，保持其 upstream core、许可和 Git 提交。

`tinyexpr` 使用既有 `patch_tinyexpr` 与 `validate_tinyexpr`，保留 `.c.o` 后缀规则、两个对象和 `make example`。实际行为由项目内 `course/verify_example.py` 验证，包含头文件变动后重编译与干净构建对照。新入口既可接 H2，也继续接 TinyExpr。

所有修复先在独立目标副本及验证沙箱中进行。原输入仓库保存前后完整 HEAD、Git 状态和全部跟踪文件的原始字节哈希。验证拒绝或最终动态重检失败时，目标副本的 Makefile 恢复到检出时的字节；保留失败日志与沙箱。

## 输出与错误处理

| 文件或字段 | 含义 |
| --- | --- |
| `result.json` | `status=SUCCEEDED/FAILED`、`input`、`validation`、源码保护结论和结构化错误 |
| `consumed-report.json`、`producer-result.json` | 实际消费的报告字节及生产清单；后者按输入是否存在保存 |
| `candidate.patch`、`repair-plan.json`、`repair.json` | 生成补丁、编辑计划和输入报告关联 |
| `validation/validation.json` | 接受/拒绝、各验证检查、回滚和错误信息 |
| `recheck.json`、`final-full/` | 接受验证后对目标副本做动态全量重检，保留实际图、声明图、Make 数据库和 strace |
| `source-before/after.json`、`source-head-before/after.log`、`source-before/after.log` | 原仓库跟踪文件哈希、完整 HEAD 与状态 |
| `target-before/after.json`、`target-head-before/after.log` | 可修改目标副本的文件哈希与 HEAD |

CLI 成功退出 0，失败退出 1。常见错误码包括 `INVALID_REQUEST`、`STALE_REPORT`、`SCHEMA_MISMATCH`、`UPSTREAM_FAILED`、`ARTIFACT_TYPE_MISMATCH`、`ARTIFACT_HASH_MISMATCH`、`ARTIFACT_ID_MISMATCH`、`UNSUPPORTED_TARGET`、`NO_MISSING_DEPENDENCY`、`REPAIR_REJECTED`、`RECHECK_FAILED` 和 `SOURCE_CHANGED`。旧补丁器的路径错误保留在 `error.message`，兜底代码为 `EXECUTION_FAILED`。目录已存在或请求缺基本路径等调用错误由 Python 异常或 CLI 非零退出反馈，HTTP 层按自身接口契约映射。

`repair.json` 表示候选已生成，最终接受应同时看 `result.status`、`validation.accepted` 和动态重检。首次输入校验失败时后续补丁文件可能尚未生成。
