## 对象依赖使用附加声明

TinyExpr 通过 `.c.o` 后缀规则构建对象，原补丁生成器要求显式目标声明。为选定的 `example.o`、`tinyexpr.o` 增加 prerequisite-only 规则，并使用 `append_rules_for` 显式允许列表控制入口。已有调用者默认参数为空。沿用原去重、路径边界和符号链接检查，减少平行实现。结果是两条头文件依赖编辑，既保留 recipe，也保留 GCC 和链接参数。支持范围由项目构建图约束，超出范围的对象直接拒绝。[适配入口](../../../../labs/e11e12/tinyexpr_repair.py) · [原补丁逻辑](../../../../labs/e8e10/lab.py)

## 用重编译和干净构建验证修复

原输出正确不能检出遗漏依赖。验证在沙箱内执行，按序检查补丁应用、recipe、构建、独立行为、无改动不重建、改头文件后两个对象及链接重建、同一输入的增量与干净构建一致、完整选定图动态重检无 MD。注释探针用于触发头文件变动，独立行为检查按 `sqrt(231)` 验证实际程序。该判据验证依赖触发关系及本项目的输出，覆盖范围是 `make example`。漏修反例的行为检查通过而重编译和 MD 检查失败，证明这些检查能区分该回归。[正反原件与哈希](evidence/tinyexpr-member2-supplement.zip)

## 通过后写回目标副本

源仓库提供 Git 历史，目标副本按完整提交检出，验证沙箱接收候选补丁。全部检查通过才把 Makefile 写回目标副本，拒绝时保留目标副本原字节。源保护独立取 23 个文件的哈希、Git 状态和差异摘要。CRLF 规范化哈希仅用来解释状态差异，前后保护仍比较原始字节。[个人报告中的保护证据说明](个人报告.md)
