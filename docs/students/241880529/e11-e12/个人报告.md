## 修复验证与回滚

正向验证先在沙箱应用补丁，清理、构建并独立检查行为。未改输入时确认不会重建，再向 `tinyexpr.h` 增加注释，确认两个对象及可执行文件的修改时间均推进。增量产物与同一输入的干净构建逐项比较 SHA-256 和输出。恢复头文件后重跑真实 strace 动态检测，选定图中剩余 MD 为 0。八项检查均通过后，才将 Makefile 写入目标工作副本。[补交验证证据](evidence/tinyexpr-member2-supplement.zip)

反向报告故意省去 `tinyexpr.o → tinyexpr.h`。候选能构建且原输出正确，但改头文件后漏重编译一个对象，动态重检仍发现 MD，结果为 `REPAIR_REJECTED`、`rollback=true`。补采时对原输入仓库的 23 个跟踪文件逐项取前后哈希，正反两次均相同。目标副本的哈希以 Git 提交对象为基准，正向仅 Makefile 改变，反向 23 个文件均匹配。原状态中 21 个 `M` 来自 Windows CRLF，转 LF 后与提交匹配，`git diff --summary` 为空。证据分别位于 ZIP 的 `source-audit/accept/`、`source-audit/reject/`。
