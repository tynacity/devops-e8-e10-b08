## 6. 个人新增测试

新增方法：`test_compile_failure_rejected_without_source_changes`。辅助方法 `check_compile_failure(root)` 允许在新目录中保留同一用例的输入与报告；常规 unittest 使用临时目录。

### 输入与独立预期

1. 创建新的显式 C/Make 样例，不破坏其 C 源码。
2. 在候选中补上 `config.h`，同时故意给 main.o 的 GCC 命令加入非法选项 `-fmember3-reject-probe`。
3. 使用合法 unified diff，预期 Patch 可应用，但构建失败；应拒绝、不写回源文件，并保留失败 sandbox。

与教师示例直接把 main.c 改成非法 C 语句不同，本用例将故障放在候选补丁中，检查“错误候选不能污染原项目”。非法编译参数仅用于负面测试，不是交付的修复策略。

### 实际结果

- `patch_applies=true`，sandbox 中确实出现新增依赖与非法参数。
- GCC 报 `unrecognized command-line option`，`error` 包含 `COMMAND_FAILED ['make', 'app']` 和指定参数。
- `accepted=false, rollback=true, source_unchanged=true`。
- `source-before.Makefile` 与 `source-after.Makefile` 字节相同；Makefile、两份 C 文件、三份头文件及 `.gitignore` 共 7 个输入文件前后 SHA-256 全部一致。

构建异常发生时，参考实现尚未写入 `checks.build`，所以实际 JSON 只有 `checks.patch_applies`。测试使用 `checks.get('build', False)` 判断构建未成功，同时核对具体错误，未将“字段缺失”写成实际返回了 `build=false`。

新增定向测试为 1 项，退出 0；完整测试为 22 项，退出 0，均显示 `OK`。完整测试由 21 项已有测试和本次新增 1 项组成，不把全套测试算作个人新增。
