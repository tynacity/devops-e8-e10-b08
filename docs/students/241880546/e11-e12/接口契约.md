# E11/E12 成员3集成接口

使用 `e11e12-1`。本阶段为固定样例与共享API的独立验收，检测使用组内已有教学适配器；A组真实TinyExpr报告消费另行联调。

|接口|内容|HTTP状态|
|---|---|---|
|POST `/v1/jobs`|JSON：`idempotency_key`和`input`；input含mode、repo、base、target，以及B/E12的candidate|202；输入错误400；同键不同输入409|
|GET `/v1/jobs/{job_id}`|状态、完成后的trace_id、失败时error|200；不存在404|
|GET `/v1/jobs/{job_id}/artifacts`|原始result.json和阶段/文件URI、SHA-256|200；结果尚未生成409|
|GET `/v1/jobs/{job_id}/files/{relative}`|产物原始字节及`X-Content-SHA256`|200；不存在、越界或Git内部路径404|

请求路径位于API服务器挂载的`/course/data`，实际输入准备到该服务器的个人仓库。服务绑定宿主`127.0.0.1`，跨主机使用SSH转发。`run_e11e12.py serve --store-root work/<个人目录>`支持独立持久化目录；默认仍为`work/api-jobs`。

同键同输入返回相同job_id，不重复调度。重启恢复时，QUEUED/RUNNING任务转为FAILED并记录SERVER_RESTARTED；已完成任务和幂等记录保留。重新执行失败输入时使用新键。

E12的draft、full-check、incremental-check、repair、recheck共享外层job_id/trace_id。full-check属于base，其他阶段属于target；独立DRAFT/BuildChecker内部trace保留。repair消费本轮incremental-check封装，先核对schema、kind、status、commit与文件哈希。外部A/B任务保留各自真实ID，通过产物URI和哈希关联。

下载字节SHA-256、manifest SHA-256及响应头SHA-256必须一致。只修改报告schema、commit、kind或文件内容的负例分别记录拒绝码，不修改原始产物。

## DRAFT执行环境

固定样例使用本人成员3的`fixtures/e11e12/fixed-runtime-candidate.Dockerfile`，在成员1原构建流程上增加Git/strace及镜像源配置；原交接候选保留。候选SHA和实际image_id随运行记录，不能沿用旧候选哈希。

base全量、依赖扫描、target增量/全量对照、补丁生成、验证及最终全量重检均在本轮DRAFT image_id内执行。每条Docker命令和当前base/target副本挂载见`execution-runtime.json`。`E11_HOST_ROOT`由宿主入口传入，避免兄弟容器错误挂载宿主不存在的`/course`或读取镜像内旧源码。
