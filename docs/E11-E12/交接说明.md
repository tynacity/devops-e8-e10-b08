## 4 TinyExpr 的共同约定

| 项目 | 本次范围 |
| --- | --- |
| 清理与构建 | `make clean`、`make example` |
| 运行 | `./example`，退出 0 |
| 输出验证 | `python3 course/verify_example.py`；完整输出见输入 JSON，数值为 `sqrt(231)` 四舍五入至 6 位小数，即 `15.198684` |
| 附加回归 | `make smoke`；不混入本次依赖图验收范围 |
| 对象与链接 | `example.o`、`tinyexpr.o` 和 `example` |
| 编译与链接参数 | `CC=gcc`、`CCFLAGS=-Wall -Wshadow -O2`、`LFLAGS=-lm` |
| 规则 | 原有 `.c.o` 后缀规则，保留其他上游源码 |
| 缺失依赖 | 两个对象都应依赖 `tinyexpr.h` |
| 最终判定 | 补丁可应用、构建及实际行为通过、头文件变化触发重编译、结果与干净构建一致、选定图动态重检无 MD；RD 可保留 |

全量、增量、补丁验证和最终重检必须遵守同一范围。EChecker 的对象发现与全量图对象投影作对照；最终重检仍检查选定图内所有实际目标，不能过滤掉未修复的 MD。不能把程序改成固定输出，也不能删除额外 C 文件来通过模板限制。
