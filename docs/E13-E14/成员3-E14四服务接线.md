## 接线范围

- 请求仍使用 `mode=e12`。指定 `profile=explicit` 或 `profile=tinyexpr` 走配对项目路径；不指定 `profile` 时保留原固定样例路径及结果格式。原 A 报告的 `e13-b` 消费请求仍用既有入口，不混入本次新检测的五阶段。
- DRAFT 核对程序输出和实际 Docker 镜像 ID 后，给本次 job/trace、目标提交和 profile 绑定镜像。只有 DRAFT 仍挂载 Docker socket；其 `/v1/runtime` 只接受该任务约定的有序阶段，不接受镜像、命令或项目路径覆盖。其他三个角色仍处理各自的 `/v1/run` 接口。角色请求响应和实际 Docker 调用记录分别保存。
- BuildChecker 与 EChecker 使用同轮 DRAFT 镜像；TinyExpr 固定检测器需恢复在 `data/tinyexpr-a-detector`。EChecker 对照全量图和增量结果，写同轮增量报告及含字节数、哈希、目标 SHA、job/trace 的生产清单。
- MDFixer 调用成员 2 的 `repair`，校验生产清单及报告字节，返回补丁和独立修复副本；BuildChecker 从该修复副本做最终动态重检。原项目 HEAD、Git 状态和跟踪文件 SHA 前后独立对照。
- 配对项目的 DRAFT HTTP 等待预算覆盖两次构建（`2 × build_timeout + 120` 秒）；TinyExpr 的 2400 秒构建配置不再被固定的 720 秒请求超时截断。这不代表容器超时清理已实测。
